  GRUPO 1 — HTML & DOM (Substituir html5ever + kuchiki)
  ──────────────────────────────────────────────────────

  [ ]  AFS-1  ACE-HTML parser próprio (lexer + tokenizer + tree builder)
         → Substituir: html5ever (0.25)
         O que fazer:
           1. Criar src/ace/html/lexer.rs — Scanner de caracteres que emite tokens brutos
              (start tag, end tag, comment, doctype, character data, EOF).
              Implementar a state machine do HTML5 spec (§13.2.5) com ~80 estados:
              Data, TagOpen, TagName, BeforeAttributeName, AttributeName,
              AfterAttributeName, AttributeValue*, SelfClosingStartTag, etc.
              Tratar character references (&amp; &lt; &#x27; etc.) com tabela de entidades.
           2. Criar src/ace/html/tokenizer.rs — Converte tokens brutos em tokens tipados
              (StartTag{name, attributes, self_closing}, EndTag{name}, Character{data},
              Comment{data}, DOCTYPE{name, public_id, system_id, force_quirks}).
              Implementar error handling com recovery (spec diz "parse error, ignore token").
           3. Criar src/ace/html/tree_builder.rs — Consome tokens e constrói a DOM tree.
              Implementar o algoritmo de tree construction (§13.2.6) com insertion modes:
              Initial, BeforeHtml, BeforeHead, InHead, InHeadNoscript, AfterHead,
              InBody, Text, InTable, InTableText, InCaption, InColumnGroup,
              InTableBody, InRow, InCell, InSelect, InSelectInTable,
              InTemplate, AfterBody, InFrameset, AfterFrameset, AfterAfterBody.
              Implementar "adoption agency algorithm" para tags formatadoras.
              Implementar "foster parenting" para nós inseridos em contextos errados.
              Implementar stack de elementos abertos e lista de active formatting elements.
           4. Criar src/ace/html/entities.rs — Tabela de named character references
              (~2200 entidades do HTML5 spec) via HashMap<&str, &str> gerado por build script
              ou const array.
           5. Criar tests/ace_html_tests.rs — Suite de testes contra html5lib-tests
              (dataset público: ~2800 test cases de tree construction).
         Arquivos atuais que usam html5ever (a migrar depois):
           - engine/dom/mod.rs (parsing principal)
           - engine/mod.rs (build_layout_tree usa NodeData de kuchiki)
         Estimativa: ~3.000-5.000 LOC | ~200-400h
         Critério de aceite: paridade com html5ever nos html5lib-tests (≥95%).

  [ ]  AFS-2  AceDOM 100% próprio (sem kuchiki)
         → Substituir: kuchiki (0.8)
         O que fazer:
           1. Criar src/ace/html/dom.rs — Estrutura de dados da DOM tree.
              Implementar Node como arena-allocated (Vec<Node> + NodeId = usize).
              Cada Node contém: parent, first_child, last_child, prev_sibling,
              next_sibling (todos Option<NodeId>), node_type (Element/Text/Comment/
              Document/DocumentFragment/DocumentType), e data específica por tipo.
              ElementData: tag_name (intern/enum), namespace, attributes (Vec<Attr>),
              id (cached Option<String>), class_list (cached Vec<String>).
           2. Criar src/ace/html/dom_ops.rs — Operações de manipulação:
              append_child, remove_child, insert_before, replace_child,

           3. Criar src/ace/html/selectors.rs — Query engine de seletores CSS no DOM.
              Implementar querySelector/querySelectorAll com parser de seletores:
              type selectors (div, p), class (.foo), id (#bar), attribute ([href]),
              combinators (descendant, child >, sibling ~, adjacent +),
