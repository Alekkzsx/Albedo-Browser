                          💡  PRINCÍPIOS DO PROJETO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. 🎯  BROWSER REAL, NÃO EXPERIMENTAL
     O Albedo é um browser de produção. Cada decisão deve considerar o impacto
     para usuários reais navegando na web real.

  2. 🦀  RUST-FIRST
     Escrito inteiramente em Rust. A segurança de memória e performance são
     vantagens competitivas reais sobre browsers escritos em C++.

  3. ⚡  PERFORMANCE É FEATURE
     Um browser lento é um browser ruim. Incremental layout, GPU compositing
     e rendering eficiente são tão importantes quanto novas APIs.

  4. 🔐  SEGURANÇA É INEGOCIÁVEL
     Sandboxing, site isolation, SRI e validação de TLS são requisitos, não extras.
     O browser toca na internet aberta — segurança é prioridade máxima.

  5. 🌐  COMPATIBILIDADE WEB ACIMA DE TUDO
     Se um site funciona no Firefox, deve funcionar no Albedo. A spec W3C é
     a referência. O objetivo é passar nos web-platform-tests (WPT).

  6. 🧪  TESTAR TUDO — E TESTAR VERDADEIRAMENTE
     Cada feature marcada como ✅ precisa de testes que provam a funcionalidade.
     Stubs com API surface não contam como implementados.
     Status honesto > ilusão de progresso.

  7. 📦  SHIPABLE MATTERS
     Build system, packaging e auto-update são parte do produto, não afterthought.
     Um browser que não instala facilmente não existe para o usuário final.

  8. 📊  PLANO COMO DOCUMENTO VIVO
     O PLAN.txt deve refletir a realidade do código, não aspirações.
     Após cada sessão: atualizar status, data e métricas.
     Contar LOC: find src -name "*.rs" | xargs wc -l | tail -1
