                          O QUE É O ALBEDO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  O Albedo é um navegador web completo, escrito em Rust, com motor próprio.

  O Chrome tem o Blink. O Firefox tem o Gecko. O Safari tem o WebKit.
  O Albedo tem o ACE.

  O ACE (Albedo Core Engine) é o motor do Albedo. Ele não é um fork do Chromium,
  não é baseado no Gecko, não usa o WebKit. É uma engine independente, construída
  pelo projeto Albedo.

  Assim como o Blink internamente usa Skia, BoringSSL, zlib e ICU como ferramentas,
  o ACE internamente usa as melhores crates Rust como ferramentas:
  html5ever, cssparser, taffy, tiny-skia, wgpu, QuickJS, rustls, e mais.

  O valor do ACE está na ARQUITETURA — no pipeline, na orquestração,
  na integração eficiente de componentes — não em reinventar cada peça.

  O objetivo: ser um browser tão capaz quanto Chrome/Firefox, mas
  BIZARRAMENTE mais leve.

                          METAS DE LEVEZA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌────────────────────────────┬────────────┬────────────┬────────────┐
  │ Métrica                    │ 🌑 Albedo  │ Chrome     │ Firefox    │
  ├────────────────────────────┼────────────┼────────────┼────────────┤
  │ RAM por aba (idle)         │ < 5 MB     │ 50-80 MB   │ 30-50 MB   │
  │ Startup (cold)             │ < 50 ms    │ 2000-5000  │ 1000-3000  │
  │ Tamanho do binário         │ < 15 MB    │ ~200 MB    │ ~100 MB    │
  │ Processos em idle          │ 1          │ 15-30      │ 8-15       │
  │ CPU em idle (%)            │ < 0.1%     │ 1-5%       │ 0.5-2%     │
  │ Tempo p/ first paint       │ < 100 ms   │ ~300 ms    │ ~400 ms    │
  │ Telemetria enviada         │ ZERO       │ Constante  │ Opcional   │
  │ Processos de background    │ ZERO       │ 3-5        │ 1-3        │
  └────────────────────────────┴────────────┴────────────┴────────────┘

  Por que o Albedo consegue ser tão leve:
  • Rust: zero garbage collector, controle total de memória
  • Single-process + async (Tokio): sem overhead de IPC entre processos
  • Zero telemetria, zero serviços de background
  • QuickJS como JS engine (~300KB vs V8 ~30MB)
  • Sem 25 anos de código legado acumulado

  Pipeline: HTML → DOM → CSS → Estilos Computados → Layout → Paint → Composição

                          ALBEDOJIT — INTEGRAÇÃO ATIVA E CONTÍNUA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  O AlbedoJIT foi promovido a pilar central do Albedo Browser e está sendo
  ativamente integrado a partir da Fase 1, operando como motor de execução principal
  junto com o rquickjs em arquitetura híbrida.

  Arquitetura de Compilação Híbrida Ativa:
  ┌─────────────────────────────────────────────────────────────────┐
  │  Tier 0: Interpretador AIR (cold code, startup rápido)         │
  │  Tier 1: Baseline JIT via Cranelift (compilação sem otim.)      │
  │  Tier 2: AlbedoTurbo (otimizações avançadas, type feedback)     │
  │  Bailout → Reversão para Tier 0/1 se type guard de deopt falhar │
  └─────────────────────────────────────────────────────────────────┘

  Roadmap de Execução Ativo:
  JIT-1 [Concluído]: Pipeline mínimo (AIR, assembler Cranelift nativo)
  JIT-2 [Concluído]: Type specialization (IC Slots, OSR e Deopt implementados)
  JIT-3 [Concluído]: Otimizações Tier 2 (Escape Analysis, Scalar Replacement, Loop Opts como LICM, Unrolling, Peeling, Versioning implementados no Tier2Compiler)
  JIT-4 [Pendente]: Garbage collector geracional concorrente com write barriers
  JIT-5 [Pendente]: DOM fast path (Rust->Rust bindings sem overhead de FFI)
  JIT-6 [Pendente]: Conformance total (suíte Test262 >= 95%, fuzzing)
  JIT-7 [Pendente]: Cutover (substituição completa de runtime quickjs se viável)

  Metas: Compilação nativa superando interpretadores puros, latência de inicialização
  baixíssima e consumo de memória sob controle (< 10-15MB adicionais).
